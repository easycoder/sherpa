**One idea, four generations.** These folders are successive attempts at the same product: turn a phone into a spoken guide for a place or a route.

| Generation | Where | What it was |
|---|---|---|
| My Guide (2012–13) | `Sherpa/www/myguide.pdf` | Android app `net.memabilia.myguide`; empty-market "how to build a Guide" manual |
| Sherpa (2013–15) | `Sherpa/` (PHP "Target CMS" site + app API; MySQL data) | "GPS logger and audio walking guide" that actually shipped, with users |
| Scanna Pro / EasyCoder (2015–17) | `ScannaPro/` (Android app + the `easycoder` DSL) | Barcode/beacon/geo "pages" plus on-phone scripting |
| AllSpeak (now) | this repo (`asedit.allspeak`, `server.allspeak`) | The modern JS/Python language + browser runtime + editor |

**The core concept is already fully specified.** `myguide.pdf` is the product spec, not just a how-to. It defines the whole model: a Guide is an ordered route of Steps; each Step has a location, a photo, and two synthesised messages (`On Arrival`, `On Departure`); the author captures a route by physically walking it; the user follows it and hears each step; if more than 1 km from the route, it drops into manual/demo mode; a live map overlay shows the route. Publishing is by keyword, with a leading `#` meaning private.

**Sherpa is that concept, shipped and wired to a server.** `Sherpa/target.php` + `php/` is a PHP MVC CMS; `php/app/appuser.php` is the phone's HTTP API. The full protocol, verbatim from the source: `register`, `login`, `help`, `publish`, `findGuides` (bounding-box query), `search` (keywords, `#`-prefixed excluded from public), `getAttributes`, `getGuide`, `uploadImage`/`downloadImage` (base64), `delete`, `checkRevisions` (sync), `sendLog` (crash reports). A guide is one URL-encoded text blob in `guides.content` holding `attributes` + `route`; steps live in `steps`/`stepcontent`. Published guides get a QR code (`php/lib/phpqrcode.php`) and the `.htaccess` maps a short code to `?c=<code>` so scanning downloads the route. Real fields (from `guidecontent.txt`/`steps.txt`): guide → `name, synopsis, keywords, runMode(manual|guided|barcode), icon, image, onarrival, ondeparture, revision, published, tags, location`; step → `name, title, image, onarrival, ondeparture, description, location(lat+lon)`.

**It had real data and real users.** `appuser` AUTO_INCREMENT ~844, `downloads` ~214, `crash` ~310, `spider` ~8.9k, hit logs from 2012-05 to 2015. The exports contain genuine content — e.g. `CTM: Historic Cars`, a Coventry museum audio guide (Hillman Minx, Payne & Bates, Maudslay Tourer...). That is a ready-made demo/fixture. The `content` table also holds finished English marketing/help copy (`sherpa`, `publish`, `guide`, `using-sherpa`, `my-guides`, `viewing`, `editing`, `step editor`).

**Scanna Pro is the DSL lineage and a second product model.** `docs/History.md` + `InsideEasyCoder.md` describe exactly the philosophy AllSpeak inherits (English-like, package-based, "if computers are so smart why can't they understand me"; the code even carries a 1999 "Linguist" copyleft). Its feature surface is the blueprint for the vocabulary a guide app needs: `speak`, `location`/`latitude`/`longitude`/`distanceTo`, `map`/markers, `gallery`/camera, `send`/`get`, `upload`, `cache`, beacon scan. Its data model (`domain/Page.java`) is the complementary "POI page" idea (barcode/beacon/location pinned content) rather than a route.

**The target platform and its gaps.** AllSpeak today is a good fit for the app shell: Webson (`.json`) for layout, `.allspeak` for logic, module/plugin architecture, language packs, and a `gmap` plugin already provides Google Maps + markers. But — checked against the runtime and the full `learn/` index — the **browser runtime has no geolocation, no speech synthesis, no camera, no barcode, and no PWA/service-worker support**. `allspeak-min.js` exposes only `localStorage` and `navigator.userAgent`. So the single biggest piece of net-new work is the vocabulary, not the app.

**Reuse verdict**

Reuse: `myguide.pdf` (requirements + onboarding copy); Sherpa help/marketing prose (already English); the Sherpa data model + `appuser` protocol (blueprint for a JSON schema and an optional sync API); exported real guide data (seed/fixtures); the `AndroidK*` keyword list (blueprint for new AllSpeak domains).

Don't reuse: the Target CMS PHP, `edit_area`, `ckeditor`, jQuery 1.4, the Android/Java, dead Play Store and `sherpa.guide`/`memabilia.net` links. Keep them as archive only.
